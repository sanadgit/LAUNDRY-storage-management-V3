# خطة أمان صفحة Track Order

## الهدف

ربط صفحة تتبع الطلبات بأرقام الطلبات القادمة من نظام POS، مع منع عرض تفاصيل الطلب للزائر غير المسجل إلا بعد تأكيد ملكية رقم الهاتف المرتبط بالطلب عبر كود واتساب.

## المنطق الصحيح

1. العميل يدخل رقم الطلب، مثل `264602`.
2. الخادم يبحث عن الطلب في:
   - رقم الطلب الداخلي `id`.
   - رقم POS `posOrderNo`.
   - رقم النظام `systemOrderId`.
   - بيانات POS المحفوظة داخل الطلب.
   - مصدر POS المباشر عند توفر الاتصال.
3. إذا وجد الطلب، لا يتم عرض أي بيانات حساسة.
4. الخادم يستخرج رقم الهاتف المرتبط بالطلب، مثل `0568720885`.
5. تظهر للعميل رسالة آمنة:
   - `تم إرسال كود لتأكيد رقم الهاتف للأمان إلى الرقم *******885`
6. يتم إرسال كود عبر واتساب إلى رقم الهاتف المرتبط بالطلب.
7. عند إدخال الكود الصحيح، يعرض الموقع تفاصيل التتبع.
8. إذا كان العميل مسجل دخول، يمكن عرض طلباته من حسابه مباشرة لأن الجلسة موثقة.

## قواعد الأمان

- لا تعتمد الواجهة على إخفاء البيانات فقط.
- لا تعرض رقم الهاتف كاملًا في صفحة التتبع العامة.
- لا تعرض حالة الطلب أو الاسم أو الفرع قبل التحقق.
- لا تسمح بالتحقق برقم هاتف يدخله المستخدم يدويًا؛ الرقم يجب أن يأتي من بيانات الطلب أو POS.
- افصل غرض OTP للتتبع عن OTP تسجيل الدخول والتسجيل باسم `track_order`.
- عند فشل الكود أو انتهاء صلاحيته، لا تعرض تفاصيل الطلب.
- في الإنتاج لا يظهر كود التطوير `dev_code`.

## ما تم تنفيذه

- API لطلب كود تحقق آمن:
  - `POST /api/customer/orders/public-track/request-verification`
- API للتحقق وإرجاع الطلب بعد الكود:
  - `POST /api/customer/orders/public-track/verify`
- دعم البحث بالحقول:
  - `id`
  - `systemOrderId`
  - `posOrderNo`
  - `pos.order_no`
  - `pos.system_order_id`
  - `pos.source_orders_id`
  - `pos.invoice_no`
- إضافة مثال اختبار:
  - رقم الطلب: `264602`
  - رقم الهاتف المرتبط: `0568720885`
  - العرض الآمن: `*******885`
- تحديث واجهة Track Order إلى ثلاث حالات:
  - بحث.
  - تحقق واتساب.
  - عرض النتيجة بعد التحقق.

## ملاحظات الإنتاج

- المثال `264602` موجود كـ fallback اختبار فقط، ويجب إزالته أو استبداله بمصدر POS الحقيقي قبل الإطلاق النهائي.
- عند استخدام Meta WhatsApp يجب ضبط متغيرات البيئة الخاصة بالقالب والرقم.
- عند استخدام AIPSoft يجب ضبط مفاتيح الإرسال والتحقق.
- يجب إضافة rate limiting أقوى حسب IP ورقم الطلب قبل الإطلاق العام.
